# cursorwrap：搜索动作与调参窗口改进方案

[English](sdk-upgrade-plan.en.md)

## 改动原因

搜索栏通过多层菜单承载全部十四项设置，日常启停与测量调参混在一起。阈值需要结合测量带、直方图和建议值理解，适合在独立窗口集中编辑。

插件已有宿主回写，应沿用这条路径。`src/main.cpp::query()` 当前会直接调用 `applyCommand()`，部分调参命令也会在查询时切换窗口状态，导致输入过程改变运行配置。查询应展示待执行动作，用户按 Enter 后才应用。

## 界面分工

| 入口 | 内容 |
|---|---|
| 搜索首页 | 回绕状态、方向、撞击模式、调参窗口和数据窗口入口 |
| 直接命令 | 保留数值和激活方式等命令，显示目标值和“应用”动作 |
| 宿主卡片 | 方向、激活方式、拖拽时禁用、单屏禁用、撞击模式 |
| 独立调参窗口 | 公共配置，速度、加速度、测量带宽、防震距离、邻接容差、边缘阈值、可视化、光效、数据窗口和建议值 |

插件运行时的启停状态与宿主启用整个插件的开关保持各自含义，不额外引入一个持久化总开关。

## 实现方案

1. 更新 SDK，以 `updateSettings()` 回写公共配置；宿主下发时只应用，不回发。
2. 将命令解析和状态变更分离。查询展示目标值；应用、重置、可视化切换和采用建议值统一在 `action()` 执行。
3. 沿用当前原生 UI 技术增加设置窗口，接入 `settingsWindow` 和 `showSettings()`；复用搜索设置入口，关注现有 64 MB 内存预算。
4. 复用设置字段定义和范围校验。搜索与控件提交后经过同一更新路径，再传给引擎、钩子和相关窗口。
5. 公共项由宿主保存；移出清单的高级项由插件保存。移除声明前确认并转存已有值，不恢复会压过宿主新修改的旧覆盖优先级。
6. 文件写入、通知和窗口操作继续放在低级鼠标钩子之外，遵循现有线程交接方式。
7. 数值范围与算法含义不变。加速度的 0 表示关闭，使用关闭选项和独立非零阈值输入，避免滑块步长破坏有效值。

独立窗口同时展示已有测量摘要和建议值，采用建议必须由用户明确执行。

## 验收标准

- 查询数值、重置和可视化命令不会直接修改状态；执行动作后才生效。
- 公共项在宿主和窗口之间同步，重启后保留。
- 高级项及当前允许的自定义数值完整保留，显示准确。
- 修改单项不重置其他参数；建议值应用到引擎实际使用的同一配置。
- 关闭和重开设置不改变回绕状态。
- 使用相关解析、设置和协议测试验证动作语义；界面与逻辑验证优先使用 `cw_devshell`。

真实钩子、光标移动和手感验证按仓库约定单独取得授权。方向、测量窗口、带宽硬边界及加速度判定语义保持不变。

## 文档更新

更新命令说明，区分查询预览与执行应用；介绍精简首页、调参窗口和计量单位。配置归属说明与实际实现一致。
